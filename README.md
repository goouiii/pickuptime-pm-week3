# 픽업타임 · 화면설계서와 기능명세서 + Live Demo

쉬는 시간 전에 교내 카페 음료를 미리 주문하고, 예상 픽업 시간에 맞춰 줄 없이 받아가는 서비스 **픽업타임**의 화면 정의서·기능명세서·와이어프레임을 화면별로 함께 읽고, 실제로 눌러볼 수 있는 데모까지 확인하는 사이트입니다. (잇타 10기 PM 스터디 3주차)

**배포 URL:** https://goouiii.github.io/pickuptime-pm-week3/  
**명세 원문(Notion):** https://app.notion.com/p/4224aecd0f9b81128a7dd6fd50c01d45

## 메뉴

- **전체 흐름 보기** — 화면 11개 카드(ID·유형, 작은 정적 미리보기, 목적, 다음 이동 경로)와 2주차 User Flow의 핵심 흐름. 카드의 `문서 보기` / `시연하기`로 각각 진입합니다.
- **문서 보기** (첫 진입 화면) — 화면 개요 → 주요 동작·상태/예외 → 큰 프레임과 번호별 구성 요소 → 기능명세 순서로 세로로 읽습니다. 프레임은 확대·축소(25~160%)·배율 슬라이더·화면 맞춤을 지원하고, 원형 번호와 설명 목록을 누르면 서로 강조됩니다.
- **시연하기** — 문서와 독립된 실제 React UI. 로그인 → 알림 권한 → 매장 선택 → 메뉴 담기 → 주문서 → 결제 → 주문 상태 → 픽업까지 동작합니다. 매장 POS·PG·OS처럼 앱 밖에서 일어나는 일은 오른쪽 시뮬레이터 패널로 일으킵니다.

문서 본문과 시연 화면 사이에는 서로 이동하는 버튼이 없습니다. 상단 메뉴와 전체 흐름 카드가 각각의 진입점입니다.

| IA · User Flow · 와이어프레임 ①~⑤ | Notion `[기획 스터디] 2주차 과제 — 교내 카페 사전 주문` |
| Figma 원본 · Dev Mode 추출 코드 | **없음** — 2주차 Low-fi 와이어프레임을 기준으로 React로 화면을 재구성 |

와이어프레임이 없는 6개 화면(로그인, 알림 권한 안내, 픽업 시간 선택, 결제, 주문 내역, 마이)은 화면 정의서 기준으로 구성했고, 구성 요소 번호는 **문서용 번호 · 화면 정의서 구성 순서**입니다. 매핑 전체는 [`docs/MAPPING-QA.md`](./docs/MAPPING-QA.md)에 있습니다.

문서의 프레임 번호는 화면 컴포넌트 안의 `data-anno` 속성을 단 실제 DOM 요소 위치로 계산합니다. 문서와 시연이 같은 화면 컴포넌트를 쓰므로 디자인이 어긋나지 않고, 문서 쪽은 `inert`로 조작을 막았습니다.

## Mock 범위와 미구현

- 카카오 로그인, PG 결제, 푸시 알림, 매장 POS 연동은 실제로 처리하지 않습니다. (로그인 성공/실패, 결제 승인/실패/취소, 매장 상태 변경을 화면과 시뮬레이터로 재현)
- 매장·메뉴·대기 건수는 `src/data/mock.ts`의 고정 값이고, 현재 시각은 **10:41로 고정**입니다.
- 데모 상태는 탭 안에서만 유지되며 새로고침하면 그 화면의 기본 목업 상태로 돌아갑니다. (저장·동기화 정책은 원문 미기재 → 확인 필요)
- 기능별 구현 상태(구현됨 / 일부 구현 / Mock 재현)는 각 기능명세 카드에 표시합니다. 미구현: 예상 시간 30초 자동 갱신·조회 실패 상태, 지정 픽업 시각 경과 처리, 담는 사이 품절, 주문 취소 동시 변경 실패.

## 개발자용 실행 방법

```bash
npm install
npm run dev      # 개발 서버
npm run lint
npm run build    # dist/ 생성
```

라우팅은 HashRouter(`#/docs/SC-HOME-01`)라서 정적 호스팅 어디서든 직접 URL 진입·새로고침이 동작합니다.

## 배포

현재 GitHub Pages로 배포되어 있습니다. `main`에서 `npm run build` 후 `dist/` 내용을 `gh-pages` 브랜치에 올리면 갱신됩니다.
